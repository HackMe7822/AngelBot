Azure VM → IIS → SSL Setup Guide

AngelBot portal  •  Direct internet exposure without Cloudflare Tunnel  •  Free wildcard certificate

When to use this guide: You have moved AngelBot to an Azure VM that has a real public IP. The Cloudflare Tunnel is no longer needed — traffic flows directly from the internet through Azure's firewall to IIS on the VM.
Internet
  ↓
Cloudflare Edge  (proxy ON, SSL terminated here)
  ↓  port 443

  ↓

1 Open Port 443 in Azure NSG

Azure VMs have a Network Security Group that blocks inbound traffic by default. You must add a rule to allow HTTPS.

  1. Go to Azure Portal → search for your VM → click it.
  2. In the left panel click Networking.
  3. Click Add inbound port rule.
  4. Fill in:
    • Source: Any
    • Source port ranges: *
    • Destination: Any
    • Destination port ranges: 443
    • Protocol: TCP
    • Action: Allow
    • Priority: 300 (or any number lower than the Deny rules)
    • Name: Allow-HTTPS-443
  5. Click Add. Takes about 30 seconds to apply.
Port 80 should already be open from the install script. If not, add a second rule for port 80 the same way — Cloudflare uses it to redirect HTTP → HTTPS automatically.

Also — open port 443 in Windows Firewall on the VM

Run in cmd as Administrator on the VM:

netsh advfirewall firewall add rule name="HTTPS 443" dir=in action=allow protocol=TCP localport=443

2 Get the VM's Public IP

  1. In Azure Portal → VM → Overview.
  2. Copy the Public IP address shown there (e.g. 20.123.45.67).
Make sure the public IP is Static, not Dynamic. Azure Portal → VM → Networking → click the IP → change Assignment to Static → Save. A dynamic IP changes on every VM restart and will break DNS.

3 Generate Free Wildcard Certificate (Cloudflare Origin)

Cloudflare gives you a free wildcard certificate that covers *.creationsit.com and creationsit.com. Valid for 15 years — no renewal needed.

Important: This certificate is only trusted by Cloudflare's edge. Cloudflare proxy must stay ON (orange cloud) in DNS. If you turn the proxy off, browsers will show an untrusted cert warning. This is the normal and recommended setup.
  1. Go to Cloudflare dashboard → click creationsit.com.
  2. Left menu → SSL/TLS → Origin Server.
  3. Click Create Certificate.
  4. Settings:
    • Let Cloudflare generate a private key: selected
    • Hostnames: make sure both *.creationsit.com and creationsit.com are listed (they are added by default)
    • Certificate Validity: 15 years
  5. Click Create.
  6. You'll see two text boxes:
    • Origin Certificate — the certificate (starts with -----BEGIN CERTIFICATE-----)
    • Private Key — the key (starts with -----BEGIN PRIVATE KEY-----)
  7. Copy each and save them as files on the VM:
    • Certificate → save as C:\ssl\origin.pem
    • Private Key → save as C:\ssl\origin.key
Save these files now — Cloudflare will never show the private key again after you close this page.

4 Convert Certificate to PFX (Windows Format)

Windows and IIS need the certificate in PFX format (certificate + private key bundled together). Git is already installed on the VM — it includes OpenSSL.

Run in cmd as Administrator on the VM:

REM Create the SSL folder if not there mkdir C:\ssl REM Convert PEM + KEY to PFX (OpenSSL from Git) "C:\Program Files\Git\usr\bin\openssl.exe" pkcs12 -export ^ -out C:\ssl\angelbot.pfx ^ -inkey C:\ssl\origin.key ^ -in C:\ssl\origin.pem ^ -passout pass:angelbot123
The -passout pass:angelbot123 sets a password on the PFX. You can change angelbot123 to anything — you'll need it when importing into IIS. Or use -passout pass: (empty) for no password.

If OpenSSL is not in Git's path, find it:

where openssl REM Or search: dir "C:\Program Files\Git\usr\bin\openssl.exe"

5 Import Certificate into Windows

Run in PowerShell as Administrator on the VM:

Import-PfxCertificate ` -FilePath "C:\ssl\angelbot.pfx" ` -CertStoreLocation "Cert:\LocalMachine\My" ` -Password (ConvertTo-SecureString -String "angelbot123" -AsPlainText -Force)

The certificate is now in the Windows certificate store and ready to be picked by IIS.

To verify it imported: open certlm.msc → Personal → Certificates — you should see *.creationsit.com listed there.

6 Add HTTPS Binding in IIS

This is where you choose your hostname. You can use any subdomain of creationsit.com — trading, portal, bot, anything.

  1. Open IIS Manager on the VM (search "IIS" in Start menu → Internet Information Services Manager).
  2. In the left panel expand the server name → click Sites → click Default Web Site.
  3. In the right panel click Bindings…
  4. Click Add…
  5. Fill in:
    • Type: https
    • IP address: All Unassigned
    • Port: 443
    • Host name: trading.creationsit.com (or whatever subdomain you want)
    • SSL certificate: select *.creationsit.com from the dropdown
  6. Click OK → Close.
  7. In the right panel click Restart to restart IIS.
Because the install script already put a reverse proxy rule in C:\inetpub\wwwroot\web.config that forwards all traffic to http://localhost:8080, IIS will automatically pass the HTTPS traffic through to the AngelBot portal — no extra config needed.

7 Update DNS in Cloudflare

  1. Go to Cloudflare dashboard → creationsit.com → DNS.
  2. Find the trading record (currently a CNAME pointing to the tunnel).
  3. Click Edit → change it to:
    • Type: A
    • Name: trading
    • IPv4 address: your Azure VM public IP (from Part 2)
    • Proxy status: Proxied — keep orange cloud ON
  4. Click Save. DNS propagates in under 1 minute since it goes through Cloudflare.
Do not turn the orange cloud off. The Cloudflare Origin Certificate is only trusted by Cloudflare's edge. Proxy ON = Cloudflare handles public SSL, then forwards to your VM using the origin cert.

8 Stop and Remove the Tunnel (Cleanup)

Once the direct connection is working, the Cloudflare Tunnel is no longer needed. Run in cmd as Administrator:

REM If tunnel was installed via NSSM (AngelBot-Tunnel service): nssm stop AngelBot-Tunnel nssm remove AngelBot-Tunnel confirm REM If tunnel runs as native Windows service (cloudflared service): net stop cloudflared cloudflared service uninstall
Run only the block that matches how your tunnel is installed. Check with sc query AngelBot-Tunnel or sc query cloudflared to see which exists.

9 Verify Everything Works

1
Open https://trading.creationsit.com in a browser. Should load the AngelBot login page with a green padlock.
2
Click the padlock → Certificate → should show issuer as Cloudflare.
3
On the VM run sc query W3SVC — should show RUNNING.
4
On the VM run sc query AngelBot-Portal — should show RUNNING.
